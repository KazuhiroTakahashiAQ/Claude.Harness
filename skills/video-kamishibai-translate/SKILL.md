# 動画を紙芝居形式の日本語にまとめる

動画の全体または指定区間を、**実キャプチャ + 日本語 + (原文) + 画面内テキストの訳**のカード列にして、1ファイルのHTMLで出力する。
会議録画、講演、チュートリアル、対談、講義、ニュースなど、**ナレーション・発言と画面の両方に情報がある動画**が対象。
**出力は常に日本語**。動画の言語と種類によって、日本語の作り方が変わる (後述)。

## 導入 (他のPC・他のプロジェクトで使う)

- このフォルダごと `~/.claude/skills/` (個人用・全プロジェクト共通) か `<プロジェクト>/.claude/skills/` (プロジェクトで共有) にコピーするだけで使える。
- 以降 **`SK` = この SKILL.md があるディレクトリ**。
- 最初に `$SK/scripts/check_env.sh` を実行し、不足を確認する。導入が必要なものは、**ユーザーの承認を取ってから**導入する (OS ごとの導入方法も表示される)。
- 必要なもの
  - `ffmpeg` / `ffprobe`
  - Python 3.8 以上 (`uv` か `python3`。同梱の Python は標準ライブラリだけで動くので、仮想環境は要らない。詳しくは次の「Python の実行環境」)
  - 書き起こしの手段のどれか1つ: **whisper.cpp + ggml モデル**、**faster-whisper** (専用の仮想環境か `uv` の一時環境)、**既存の字幕ファイル** (SRT / VTT)
  - 任意: Chrome / Chromium / Edge (生成HTMLの自動検証用。無くても作れる)
- スクリプトは bash 前提。macOS と Linux で動作確認済み。Windows は Git Bash か WSL で使う (Windows 上では未検証)。
- 動画と音声は**外部に送らない**。処理はすべてローカル (ネットワークを使うのは、ツールやモデルのダウンロード時だけ)。

## Python の実行環境

- **同梱の Python スクリプト** (`build_kamishibai.py`、`srt_abs.py`) は標準ライブラリだけで動く。**仮想環境もパッケージ導入も不要**。`scripts/run_py.sh` が、次の順で Python を選んで隔離モード (`-I`) で実行する。
  1. `uv` があれば `uv run --no-project python`
  2. 無ければ、動作を確認できた `python3` (3.8 以上)、なければ `python`
- **`uv` には `--no-project` を付けている**。付けないと、実行したディレクトリが uv のプロジェクト (`pyproject.toml` がある場所) のとき、そのプロジェクトに `.venv` と `uv.lock` を作り、依存関係を導入してしまう (実際に確認した)。ユーザーのプロジェクトを汚さないための指定で、外さない。
- **faster-whisper を使うときだけ**、標準ライブラリ以外が必要になる。`prepare.sh` は次の順で選ぶ (whisper.cpp があればそちらが優先)。
  1. **専用の仮想環境** (`~/.cache/video-kamishibai-translate/venv`。`VKT_VENV` で場所を変えられる) に faster-whisper があれば、それを使う
  2. 無ければ、`uv` の一時環境 (`uv run --no-project --with faster-whisper`)。毎回の解決が必要で、初回は遅い
  3. どちらも無ければ、faster-whisper を import できる手元の Python
- **専用の仮想環境を作る手順** (faster-whisper を繰り返し使うときに安定する。ネットワークとディスク数百MBを使うので、**ユーザーの承認を取ってから**実行する):
  ```bash
  $SK/scripts/setup_env.sh --dry-run   # 作る場所・パッケージ・方法を表示するだけ (何も作らない)
  $SK/scripts/setup_env.sh             # uv で作成: uv venv + uv pip install faster-whisper
  ```
  - 作成は `uv` を使う。`uv` が無いときは、導入方法 (macOS / Linux / Windows) を案内して終わる。`uv` を導入しない場合だけ、`--allow-pip` で `python3 -m venv` + `pip` に切り替えられる (Python 3.9 以上)。
  - パッケージは、公開から7日以内のものを避けて導入する (`VKT_EXCLUDE_NEWER_DAYS` で変更、0 で無効)。公開直後の改ざんされたパッケージを拾うリスクを減らす指定。
  - 作る場所はスキル専用のキャッシュで、プロジェクトのディレクトリは変更しない。不要になれば、そのディレクトリを削除すればよい。

## 動画の種類ごとの作り方

動画の種類は、映像と書き起こしから判断する (ユーザーに聞き返さない)。判断した種類は最終報告に書く。

- **講演・セッション・ウェビナー** (スライド + 話者)
  - カード: 話の切れ目 (6〜15秒目安) と、スライドの切り替え・ビルドの両方で区切る。
  - 画面: スライドの文字を `ocr` に訳す。
  - サマリー: 主張の流れ。用語集: 分野の専門用語、製品名、略語。
- **会議・打ち合わせの録画**
  - カード: 議題・話題ごとに section を分け、1カードに1〜3発言をまとめる。`speaker` に話者を入れる。
  - 話者: 音声認識は話者を区別しない。画面の名前表示、呼びかけ、文脈から推定し、不確かなら「Aさん (推測)」「話者A」と書く。
  - 画面: 共有画面・資料のフレームを使う。参加者の顔のギャラリー映像は、既定で画像なしのカード (`frame=None`) にする。顔を載せるかは、必要ならユーザーに聞く。
  - サマリー: `blocks` に「決定事項」「論点・未決事項」「ToDo」を入れる。**担当者や期限は、実際に言われた場合だけ書く**。
  - 用語集: 社内用語、略語、プロジェクト名。人名・社名・製品名の聞き間違いが多いので、ユーザーが一覧をくれたら `WHISPER_PROMPT` に渡す。
  - 雑談・挨拶・接続トラブルなどを省く場合は、省いたことを制作メモに書く。
- **チュートリアル・操作デモ・ハンズオン**
  - カード: 操作 (手順) ごと。section を「手順1」「手順2」のようにする。
  - 画面: UI の文言を `ocr` に訳し、クリックする場所を `hl` の強調枠で示す。
  - サマリー: `blocks` に「用意するもの」「つまずきやすい点」。
- **対談・インタビュー・座談会・ポッドキャスト** (映像が話者の顔中心)
  - カード: 話題ごと。`speaker` を付ける。発言の趣旨を変えず、言い回しだけ整える。
  - 画面: 変化が少ないので、フレームは少なめにする。同じフレームを使い回すか、画像なしのカードにする。
  - サマリー: 主張と、その根拠・エピソード。
- **授業・講義・研修**
  - カード: 板書・スライドの切り替えと、話題の切れ目で区切る。
  - 画面: 板書やスライドの文字・数式を `ocr` に書く。読み取れない数式は「推測」と明記する。用語集を厚めにする。
- **ニュース・ドキュメンタリー・Vlog・その他**
  - カード: 場面 (カット) ごと。
  - 画面: 焼き込みテロップ・字幕が重要なので、`ocr` に原文→訳で書く。ナレーションが無い場面は、映像の説明を簡潔に書き、推測を含むなら明記する。

## 動画の言語ごとの方針

最初に動画の音声の言語を判定する。`prepare.sh` が自動判定して `lang.txt` に書く。ユーザーが言語を申告したらそれを優先し、判定が怪しければ `WHISPER_LANG=<コード>` を付けて `prepare.sh` をやり直す。

- **英語 (`en`)**: 日本語に翻訳し、英語原文を併記する。`SRC_LANG` は省略 (既定の `"en"`)。
- **日本語 (`ja`)**: **翻訳しない**。書き起こしを整えた日本語で紙芝居を作る。
  - `scenes.py` に `SRC_LANG = "ja"` を書き、各カードの `en` は省略する (原文欄は出ない)。
  - 整形の方針は、言い淀み・フィラー・言い直しを除く、誤変換を直す、句読点を整える、1文を短くする。**意味は変えず、要約しすぎない**。
  - 画面内テキストが日本語なら `ocr` は不要。外国語が映る場合だけ、その部分の原文→訳を書く。
  - 制作メモに「動画が日本語のため翻訳せず、書き起こしを整形した」と書く。
- **それ以外の言語 (`zh`、`ko`、`es` など)**: 日本語に翻訳し、その言語の書き起こしを `en` 欄に原文として併記する。`SRC_LANG = "<コード>"` を書く (原文欄の `lang` 属性になる)。画面内の外国語テキストは `ocr` に原文→訳で書く。
- どの言語でも、1分サマリー、用語集、制作メモは日本語で書く。ヘッダーの既定文言は `SRC_LANG` に合わせて変わる。

## 成果物の既定

- 出力は **単一HTML** (画像は base64 埋め込み)。保存先は `~/Downloads/<動画名>_<開始>_<終了>_kamishibai.html` (`~/Downloads` が無ければカレントディレクトリ)。
- 外国語の動画では原文を併記する。キャプチャは動画の実フレーム。
- ユーザーが別形式 (Marp、Markdown など) や保存先を指定したら従う。出力形式の指定がないときだけ、最初に1回確認する。
- 次の6点は、ユーザーが確認した好みなので、聞き返さずに適用する。
  1. **キャプチャは少ないより多い方がよい**。10〜15枚などと決め打ちせず、伝わりやすくなるだけ入れる (顔を載せない等の理由があるカードを除く)。
  2. **画像内の外国語テキスト (スライド、UI、チャット欄、字幕) も翻訳する**。ナレーションの訳だけで終わらせない。
  3. **最初のページは「1分サマリー」** (読了約1分、500〜700文字)。区間の流れから各場面へ飛べるボタンも付く。
  4. **初心者向けの用語解説を、スイッチなしで常に表示する**。その動画の分野の初心者向けに、用語の横へ「？」を付け、押すと意味がポップアップで出る。
  5. **日本語の文章は句点 (。) ごとに改行して表示する**。ビルド時に自動で行われる。そのため、1文を短くし、「。」は文末にだけ置く (文中や引用の中に「。」を入れない)。
  6. **文字サイズは小さめ**。本文14px、日本語訳14〜16px、補足類10〜12px が基準。変える場合は `build_kamishibai.py` の CSS だけを直す。

## 同梱ファイル

- `scripts/check_env.sh` : 必要なツール (Python のバージョンや専用の仮想環境を含む) の有無を確認し、OS ごとの導入方法を表示する (表示のみで、何も導入しない)
- `scripts/setup_env.sh` : faster-whisper 用の専用の仮想環境を uv で作る (承認制。`--dry-run` で内容だけ確認できる)
- `scripts/lib.sh` : OS・ツール・Python の違いを吸収する共通関数 (他のスクリプトが読み込む)
- `scripts/run_py.sh` : 同梱の Python を、環境にある `uv` (`--no-project`) / `python3` で隔離モード (`-I`) 実行する
- `scripts/prepare.sh` : 音声切り出し、言語判定つきの書き起こし (または既存字幕の取り込み)、画面切替検出、候補フレーム抽出を一括実行する
- `scripts/transcribe_faster_whisper.py` : whisper.cpp が無い環境用の書き起こし (prepare.sh が内部で使う)
- `scripts/srt_abs.py` : 字幕 (SRT / VTT) を動画内の絶対時刻に直す (prepare.sh が内部で使う)
- `scripts/build_kamishibai.py` : scenes.py とフレーム画像から単一HTMLを生成する (1分サマリー、カード、用語の「？」ポップアップ、用語集、制作メモ)
- `scripts/verify.sh` : 生成HTMLをヘッドレスブラウザで検証する (サマリーが先頭か、「？」が開くか、全カード巡回、画像欠落、モバイル幅のはみ出し)
- `references/scenes_template.py` : scenes.py の雛形とフィールド説明 (CARDS / SUMMARY / GLOSSARY / NOTES / SRC_LANG)

## 手順

### 0. 区間と環境の確認 (読み取りのみ)

- `$SK/scripts/check_env.sh` を実行する。不足があれば、導入方法をユーザーに伝え、承認を得てから導入する。
  書き起こしに faster-whisper を使う場合 (whisper.cpp が無いとき) は、`setup_env.sh` で専用の仮想環境を作ることを提案する (「Python の実行環境」を参照)。
- 区間を秒に直す (24:36〜29:14 → 1476〜1754)。区間の指定がなければ動画全体 (長い場合は後述の「長い動画の扱い」)。
- `ffprobe` で動画の長さ・解像度・字幕トラックの有無を確認する。字幕トラックがあれば、`ffmpeg -i <video> -map 0:s:0 <workdir>/subs.srt` で取り出して使える (ユーザーが字幕ファイルを持っていれば、それでもよい)。
- 書き起こしに whisper.cpp を使う場合は、多言語モデル (`large-v3-turbo` など) を使う。`*.en.bin` は英語専用で、英語以外の動画には使えない。
- プランモード中は、ここまでの読み取りだけを行い、導入・抽出は承認後にする。

### 1. 下準備 (書き起こし + 候補フレーム)

```bash
$SK/scripts/prepare.sh <video> <start_sec> <end_sec> <新しい空のworkdir> [step_sec]
```

- workdir は**新規の空ディレクトリ**にする (作業用の一時ディレクトリなど)。既存ファイルの削除は不要。環境によっては `rm` のワイルドカードが拒否される。
- 環境変数で挙動を変えられる。詳細は `prepare.sh` の冒頭コメントを参照。
  - `SUBTITLE_FILE=<字幕.srt|vtt>` 既存の字幕を使う (音声の書き起こしを省く。言語は `WHISPER_LANG` で指定する)
  - `ASR=whisper-cpp|faster-whisper` 書き起こしの手段を固定する (既定は自動選択)
  - `WHISPER_LANG=<コード>` 音声の言語を指定する (既定は自動判定)
  - `WHISPER_PROMPT="<人名・用語の一覧>"` 固有名詞の聞き間違いを減らす
- 音声は前後6秒の余白付きで切り出す。`transcript.txt` は動画内の絶対時刻付きなので、区間の最初の文・最後の文をここで確定する。
- `lang.txt` に判定した言語コードが入る。上の「動画の言語ごとの方針」に従う。
- `scene_changes.txt` は画面が大きく変わった秒、`cand_changes.txt` は直前から内容が変わった候補フレームの秒。

### 2. 画面を見る

- 候補フレームを Read で1枚ずつ見て、画面の内容と画面内テキストを把握する (`cand/t_<秒>.jpg`、幅1280)。
- 全体像は `ffmpeg ... -vf "fps=1/10,scale=640:-1,tile=4x7"` のコンタクトシートで先に掴む。ffmpeg のビルドによっては `drawtext` が無く、時刻ラベルを付けられない (並び順で対応づける)。
- 小さい文字 (チャット欄、集計表、キャンバス上のラベル) は、元解像度から `crop=...,scale=iw*2:-1:flags=lanczos` で切り抜いて読む。
- 映像に焼き込まれた字幕・テロップがあれば、フレームの下部などから目視で書き起こして訳す。**無ければ、その旨を最終報告に書く**。

### 3. シーン設計

- カードの区切りは、**ナレーション・発言の切れ目 (6〜15秒目安) と画面の変化の両方**で決める (種類ごとの作り方も参照)。
- 同じ画面が続いても、話題が変われば別カードにする。画面が文の途中で変わるときは、文を分けてカードを分ける。
- 使うフレームを決めたら、1600px 幅で `f_<秒>.jpg` として書き出す (別ディレクトリ `final/`)。

```bash
ffmpeg -hide_banner -loglevel error -y -ss <秒> -i <video> -frames:v 1 -vf "scale=1600:-1:flags=lanczos,format=yuvj420p" -q:v 4 final/f_<秒>.jpg
```

- 内容が同じフレームは**同じ秒のキーに寄せる** (HTML側で1回だけ埋め込まれ、容量が増えない)。
- フレームの時刻は、**必ず秒を明示して1枚ずつ切り出す**。`fps=1/N` の連番は実時間とずれる。
- `format=yuvj420p` は必須。元動画の幅が出力幅と同じ (1280px 幅など) だと、色範囲の変換が入らず JPEG の書き出しが失敗する。

### 4. 日本語の作成と scenes.py の作成

- `references/scenes_template.py` を作業用ディレクトリに `scenes.py` としてコピーし、`CARDS` を埋める。
- 日本語は紙芝居調の「です・ます」で、読み上げて自然な長さにする。製品名・機能名は原語のまま。1文を短くし、句点ごとに改行して読まれることを前提にする。
- **音声認識の聞き間違いは、スライド・画面の文字・文脈と突き合わせて補正し、補正した語を `note` と `NOTES` に必ず書く**。確信が持てない語は「聞き取り不確実」と明記し、そのまま訳出する。
- 原文 (`en`) は音声認識の結果を使い、言い淀みだけ軽く整える。語句の差し替えは補正として記録する。日本語の動画では `en` を省略する。
- 画面内テキストは `ocr=[(原文, 訳), ...]` に書く。その画面が最初に出るカードだけに書き、続くカードでは省略する。リボンやメニューの細かい文言は主要なものだけにし、網羅していないことを `NOTES` に書く。
- 映像から推測した内容 (略称の意味、話者、ハイライトの意味など) は、事実のように書かず「推測」と明記する。
- 話している領域があるときは `hl=[left%, top%, width%, height%]` で強調枠を付ける。
- **`SUMMARY` を書く** (最初のページ)。`lead` + 5つ前後の `points` (見出し `h` と説明 `t`) で、合計 500〜700 文字にする。会議や手順の動画では `blocks` を足す。
  動画に無い主張を足さず、区間の流れを順に要約する。文字数は build 時に表示され、範囲外なら警告が出る。
- **`GLOSSARY` を書く** (用語の「？」ポップアップ)。
  - その動画の分野の**初心者が引っかかる用語**を選ぶ (専門用語、略語、製品・機能名、業界用語、社内用語)。日常語は入れない。
  - `match` には、日本語・画面内テキストの訳・サマリーに**実際に出てくる表記**を入れる。長い表記は短い表記より先に照合される (「タグファミリ」と「タグ」を別項目にできる)。
  - `desc` は1〜2文の平易な説明。動画の発言ではなく訳者の補足なので、**確信が持てない説明は書かない**。書いたものも最終報告で「専門家の確認はしていない」と伝える。
  - 本文に一度も出てこない用語は build 時に「本文に出てこない用語」として表示されるので、削るか `match` を直す。
  - 「？」は同じ用語につき、1つの文章ブロックで最初の1回だけ付く。スイッチは付けず、常に表示する。

### 5. HTML 生成

```bash
$SK/scripts/run_py.sh $SK/scripts/build_kamishibai.py <scenes.pyのあるdir> <final_dir> ~/Downloads/<名前>_kamishibai.html
```

出力に `cards=N images=M glossary=G summary_chars=S` が出る。画像が多くて 20MB を超えそうなら、幅や `-q:v` を下げて再抽出する。
`scenes.py` に `TITLE` / `SUBTITLE` を書くと、ヘッダーとタブのタイトルになる (省略時は `SRC_LANG` に合わせた汎用の文言)。`GLOSSARY` を省略すると「？」も用語集も出ない。

### 6. 検証

```bash
$SK/scripts/verify.sh <html> <新しい空のtmpdir> [screenshot.png [カード番号]]
```

- 合格条件は `summaryFirst=true`、`errors=[]`、`brokenImg=0`、`emptyJa=0`、`mobile ... overflow=false`。
  用語集を付けた場合は、さらに (`qOnLoad>0` または `qCards>0`) かつ `popOpens=true` (「？」が初期状態から出て、押すと開く)。
- `first=` / `last=` が依頼の区間の開始・終了と合うことを確認する。
- スクリーンショットは Read で見て、表示崩れがないか目視する。句点ごとに改行されているか、文字が大きすぎないかも見る。
- Chrome 系ブラウザが無いと `verify.sh` は終了コード 3 で終わる。その場合は、HTML をブラウザで開いて目視で確認する。
- 翻訳 (整形) と書き起こしを突き合わせ、抜けや誤りを点検する。各キャプチャの画面内の外国語に、訳の取りこぼしがないかも確認する。

### 7. 納品

- HTML を既定のアプリで開く (`open` / `xdg-open` / `start`)。開けない環境では、出力パスをユーザーに伝える。
- 最終報告には次を書く。
  - 出力パスと構成 (カード数、画像数、容量)
  - 動画の種類の判断、言語の判定結果、翻訳したか整形だけか
  - 字幕の有無、使った書き起こし手段
  - 音声認識の補正 (一覧)、聞き取り不確実の箇所、映像からの推測 (話者など) の箇所
  - 時刻は概算であること、画面内テキストを網羅していない範囲
  - 1分サマリーと「？」の説明は動画の発言ではなく訳者の補足であること。一般知識で書いた説明 (専門家の確認はしていないもの) は、どれかを名指しで伝える
  - 環境に加えた変更 (ツールやモデルの導入など)

## 長い動画の扱い

- 区間が15分を超えると、`prepare.sh` は候補フレームの間隔を自動で広げる (15分まで4秒、1時間まで10秒、それ以上は20秒)。必要なら `step_sec` で指定する。
- 目安として、区間1分あたり2〜5カード。1時間なら100〜300カードになり、画像で HTML が重くなる。容量が20MBを超える場合は、**15〜20分ごとに区間を分けて、複数のHTMLにする**。画像なしのカード (`frame=None`) を増やすのも有効。
- 区間の指定がない長い動画では、いきなり全編を作らず、章や話題の区切りを示して、どの範囲から作るかをユーザーに確認する。
- 書き起こしの時間は、whisper.cpp (large-v3-turbo) なら実時間より短い。faster-whisper を CPU で動かすと長くかかる。

## 取り扱い上の注意

- 会議録画などは、機密情報・個人情報 (顔、氏名、社内資料) を含むことがある。処理はすべてローカルで、動画・音声・書き起こしを外部のサービスに送らない。
- 生成したHTMLには、キャプチャ画像と発言の全文が埋め込まれる。共有範囲はユーザーが決める。勝手に公開・アップロードしない。
- 顔が映るフレームや、機密資料が映るフレームを使うときは、その旨をユーザーに伝える。
- 他者の著作物の動画は、私的利用の範囲で扱う。

## 落とし穴

- `whisper-cli` のJSON出力は `-oj`。`-ojson` は「unknown argument」で使い方表示だけして終わる (prepare.sh は SRT だけを使う)。
- 後半のタイムスタンプが15秒単位に粗くなることがある。`-mc 0 -ml 110 -sow` (文脈なし、短く分割) で解消する。prepare.sh は既に指定済み。
- faster-whisper に音声ファイルのパスを渡すと、内部のデコード (PyAV) が版の組み合わせで壊れることがある。同梱の `transcribe_faster_whisper.py` は、WAV を自前で読み込んで配列を渡す。
- uv のプロジェクト内で `uv run python` を `--no-project` なしで実行すると、そのプロジェクトに `.venv` / `uv.lock` が作られ、依存関係が導入される。同梱のスクリプトは対応済みだが、このスキルの手順に Python の実行を足すときも `--no-project` を付ける。
- macOS の `python3` は、未導入だと開発者ツールの導入ダイアログが出るだけで動かないことがある。`lib.sh` は実際に動くか (3.8 以上か) を確認してから使う。
- 言語の自動判定は短い区間でも通常は当たる (英語、日本語で確認済み) が、無音・BGM が多い区間では外れうる。判定が怪しければ `WHISPER_LANG` で指定する。
- 固有名詞 (製品名、人名、略語) は音声認識で崩れやすい。同じ語が別の回で別の綴りになることもあるので、確信が持てない語は断定しない。
- 画面がほとんど動かない動画では、画面切替の検出が「該当なし」になる。prepare.sh は対応済み (`scene_changes.txt` が空になるだけ)。毎フレーム変わる映像 (カメラ映像など) では `cand_changes.txt` が役に立たない。その場合は `scene_changes.txt` と書き起こしの話題の切れ目で選ぶ。
- ヘッドレス Chrome は `--window-size` を小さくしても最小幅が効き、モバイル幅の検証にならない。iframe で測る (verify.sh は対応済み)。
- 生成HTMLの JS は `const` で状態を持つため、外から読むには `eval` を使う (verify.sh は対応済み)。
- ボタンの中に `div` を入れない (`span` にする)。サムネイル選択に `scrollIntoView` を使うとページ全体が縦スクロールするので、帯の `scrollTo` で横だけ動かす。
- `display: grid` などを指定した要素は、`hidden` 属性だけでは隠れない。CSS に `[hidden] { display: none !important; }` を入れてある。
- 用語ポップアップを scroll イベントで閉じるときは、ページ本体のスクロールだけを対象にする。サムネイル帯のスムーズスクロールでも閉じると、カード移動直後に「？」を押しても開かない。
- 用語と「？」は `white-space: nowrap` で一続きにする。行末で「？」だけが次の行に取り残されるのを防ぐ。
- サマリーの番号付きリストのスタイルは `ol` の直下に限定する。そうしないと、`blocks` の箇条書きにも番号の丸が付く。
- 文字サイズは小さめが既定。大きくしすぎると、1画面にサマリーや画像と訳が収まらず、スクロールが増える。
- ユーザーが口調を変えるモード (簡潔な口調など) を有効にしていても、生成するHTMLや `scenes.py` の日本語は通常の文体で書く。
