# sheet-preview

スプレッドシートを作る前に、内容を HTML で見て、セル範囲単位で指示を出し、直して、また見る。この往復で固めてから xlsx にする。

正本は JSON（`sheet.json`）。HTML はそれを描くだけでなく、人が画面上でセルの文字・行列・結合・色・固定行などを直接直せる（保存すると sheet.json が書き換わる）。人は直接直すか、コメント（指示）でエージェントに頼むかを選ぶ。どちらも最終的に sheet.json に入るので、xlsx 変換と見た目は食い違わない。

## ファイル

| ファイル | 役割 |
|---|---|
| `<名前>.sheet.json` | 正本。シート複数、列幅、行高、結合、色、セル値。スキーマは `references/sheet-schema.md` |
| `<名前>.review.json` | 人のコメント（指示）。range / instruction / status / agent_reply。スキーマは `references/review-schema.md` |
| `scripts/serve.ts` | localhost で HTML を配信し、「保存」で sheet.json / review.json を書く。複数ファイルをタブで配信できる。読み込み後に他の書き手が更新していたら 409 で止める（依存なし） |
| `scripts/to_xlsx.py` | sheet.json → xlsx（openpyxl、uv 経由） |
| `assets/template.html` | 描画用テンプレート（serve.ts が埋め込んで配信） |
| `examples/sample.sheet.json` | サンプル（2 シート、結合・色・幅・行列固定あり） |

作業ファイルは、依頼された場所か、作業中のプロジェクトの適当なフォルダに置く。skill のフォルダには置かない。

## 2 つの用途

最初にどちらかを決め、sheet.json の `mode` に書く（HTML ヘッダーに表示される）。

- **スキーマ確認（`"schema"`）**: 列構成・見出し・結合・色・数式の置き場所など、枠組みを決める。セル値は空やダミーでよい。「備考欄はここ」「合計行は結合したい」のような指示が中心。
- **実データ確認（`"data"`）**: 実際の値を入れて、中身の誤り・抜け・並びを確認する。「この行の単価が違う」「C 列は千円単位に」のような指示が中心。

迷ったら、データがまだ無ければ schema、あれば data。

## 手順

### 1. sheet.json を作る
依頼内容（目的、必要な列、見せたい集計など）から `<名前>.sheet.json` を書く。まず `references/sheet-schema.md` を読む。`examples/sample.sheet.json` を雛形にするとよい。ヘッダー行は色を付け、列幅は内容に合わせる。見た目の確認が目的なので、シート数・行数は確認に足りる最小限にする。

### 2. 起動して人に見せる
```bash
node <skill>/scripts/serve.ts <名前>.sheet.json            # http://localhost:8765/
node <skill>/scripts/serve.ts <名前>.sheet.json --port 8800 # ポート変更
```

**ファイルが複数あるとき**は 1 つのサーバにまとめて渡す（ファイルごとに別ポートで立てない）。画面の最上部にファイルタブが並び、切り替えて見られる。

```bash
node <skill>/scripts/serve.ts 見積書.sheet.json 請求書.sheet.json   # 複数パス
node <skill>/scripts/serve.ts <フォルダ>                             # フォルダ内の *.sheet.json を全部
```

- ファイルごとに review.json・未保存の変更・元に戻す履歴・下書き・409 の検知が独立している。1 つを保存しても他は触らない。未保存のファイルタブには ● が付き、ファイルが外部で更新されると ⚠ が付く。
- 起動後に増やすには、タブ右端の「+」にパスを入力する（無ければ空の sheet.json を新規作成。フォルダも可）。フォルダ指定で起動していれば、そこに *.sheet.json を置くだけで 3 秒以内にタブが増える。
- `--review` は 1 ファイルのときだけ使える。複数のときは各 `<名前>.review.json` が自動で使われる。
- API は `?f=<ファイル名>` でファイルを選ぶ（省略すると最初のファイル。1 ファイル起動の従来どおりの使い方もそのまま動く）。`GET /api/files` で一覧。
`node x.ts` 形式で動く（Node 22.6 以降。TypeScript の型は実行時に除去される）。バックグラウンドで起動し、URL を人に伝える。サーバを立てられない・使いたくない場合は静的 HTML を出す。

```bash
node <skill>/scripts/serve.ts <名前>.sheet.json --render <名前>.html
node <skill>/scripts/serve.ts a.sheet.json b.sheet.json --render all.html   # 複数ファイルは 1 つの HTML にタブでまとめる
```

### 3. 人が画面で直す・コメントする
人ができること（右クリックメニューかツールバー）。

- **広い作業領域**: データ範囲の外側にも、画面を埋めるまで（最低 +20 行・+8 列）うっすらした空きマスが続く。そこに入力すると、データ範囲が自動で伸びる。空きマスは保存されない（値を入れたセルだけが sheet.json に入る）。右のコメント一覧は「一覧」ボタンで折りたたみ、境界のドラッグで幅も変えられる（幅と開閉は覚えている）。
- **選択**: ドラッグ、Shift クリックで拡張、Ctrl/Cmd クリックで追加。列見出し・行見出しのクリックで列・行ごと。
- **コメント**: 範囲を選んで「コメント」。選択セルの近くに引出線つきの吹き出しが出て、右側に縦の一覧（未対応 / 対応済 / 質問、agent_reply つき）が並ぶ。一覧と吹き出しは連動する。範囲欄に `明細!B2:D5, F3` と直接打ってもよい。
- **直接編集**: ダブルクリック、または選択して文字入力 / F2 でセルを書き換え（Enter 確定、Esc 取消）。行・列の挿入・削除、見出しのドラッグでの並べ替え、結合・解除、背景色・文字色、太字・配置、行高・列幅のドラッグ、行列の固定、シートタブの追加・削除・名前変更・並べ替え。Ctrl+Z / Ctrl+Shift+Z で元に戻す・やり直す。
- 行・列を挿入・削除・並べ替えると、コメントの範囲も追従する。範囲が丸ごと消えたコメントは「対象が削除された」と出る（review.json では `deleted: true`）。

保存:
- **サーバあり**: 「保存」で sheet.json と review.json を書く。画面は読み込んだ版を覚えていて、保存時にファイルが先に更新されていれば 409 で止め、「エージェントが更新した。再読み込みするか」と出す（上書きしない）。3 秒ごとにも更新を見に行く。
- **サーバなし**: ブラウザの localStorage に退避される。「sheet.json をコピー」「指示をコピー」で JSON を出し、人がチャットに貼る。貼られた JSON はそれぞれ sheet.json / review.json として保存して続ける。

### 4. 往復（エージェントの仕事）
指示を受け取ったら、この順で処理する。

0. **人が直接直した場合、sheet.json はすでに変わっている。作業前に必ず今の sheet.json を読み直し、指示文より現在の sheet.json を優先する**（指示文の「B3 を〜に」が、すでに人が直した内容や行の挿入でずれていることがある）。`range` は行・列の編集に追従済みなので、現在の sheet.json の位置を指す。`deleted: true` の項目は対象が消えているので、`agent_reply` に「対象が削除されたため対応不要」と書いて「対応済」にするか、人に確認する。
1. `review.json` を読み、`status` が「未対応」の項目を拾う。
2. 各 `range` が指すセルを sheet.json で確認し、`instruction` どおりに sheet.json を直す。結合・色・幅など書式の指示も sheet.json 側で表現する。
3. 指示の意味が曖昧、または複数の解釈があるときは、勝手に決めず `status` を「質問」にして `agent_reply` に質問を書く。
4. 直せた項目は `status` を「対応済」にし、`agent_reply` に何をどう直したか 1〜2 文で書く。
5. 人にはブラウザの「再読み込み」を押してもらう（画面に未保存の変更があると失われるので、先に保存してもらう。エージェントが書いた後は画面に更新バナーが出る）（サーバは sheet.json / review.json を毎回ファイルから読むので、サーバの再起動は要らない。静的 HTML を使っている場合は `--render` で描き直す）。

review.json の項目は削除せず、履歴として残す。人が「質問」に答えたり、指示を書き足したりしたら、また 1 に戻る。人が「これでよい」と言うまで繰り返す。

人が「保存」を押したとき、ファイルがエージェントに更新されていれば 409 で止まるので、人の変更が黙って上書きされることも、人がエージェントの変更を上書きすることもない。ただし sheet.json を書き換える前に、人の未保存の編集が画面にあるかもしれない点に注意し、書いたらすぐ人に再読み込みを促す。

### 5. xlsx にする
```bash
uv run <skill>/scripts/to_xlsx.py <名前>.sheet.json <名前>.xlsx
```
`uv` 経由で openpyxl が自動で入る（pip は使わない）。結合・背景色・文字色・太字・配置・列幅・行高・固定行列（`freeze`）が反映される。列幅は px から文字数、行高は px から pt に近似変換する。数式（`=` で始まる値）はそのまま xlsx の数式になる。

### Google Sheets への書き込みは承認制
xlsx を Google Drive / Sheets にアップロード・書き込みするのは外部書き込み。書く内容（宛先・対象ファイル）を提示し、人の明示的な承認を得てから実行する。承認なしにしない。ローカルの xlsx 出力は承認不要。

## 指示の書き方（人向けの補足）
範囲は A1 形式。シート名は `!` の前に付ける（`明細!B2:D5`）。複数範囲はカンマ区切りで、シート名は最初の 1 回でよい（`明細!B2:D5, F3`）。別シートを混ぜるときは `明細!B2:D5, 集計!A1` のように書く。スペースや記号を含むシート名は `'月次 売上'!A1` と引用符で囲む。
