# sheet-preview

スプレッドシートを作る前に、内容を HTML で見て、セル範囲単位で指示を出し、直して、また見る。この往復で固めてから xlsx にする。

正本は JSON（`sheet.json`）。HTML はそれを描くだけでなく、人が画面上でセルの文字・行列・結合・色・固定行などを直接直せる（保存すると sheet.json が書き換わる）。人は直接直すか、コメント（指示）でエージェントに頼むかを選ぶ。どちらも最終的に sheet.json に入るので、xlsx 変換と見た目は食い違わない。

## ファイル

| ファイル | 役割 |
|---|---|
| `<名前>.sheet.json` | 正本。シート複数、列幅、行高、結合、色、セル値。スキーマは `references/sheet-schema.md` |
| `<名前>.review.json` | 人とエージェントのやり取り（スレッド）。指示・確認・メモ。スキーマは `references/review-schema.md` |
| `scripts/serve.ts` | 常駐ハブ。登録した全 sheet.json を 1 つのポートで配信し、書き込みを直列化する（依存なし） |
| `scripts/to_xlsx.py` | sheet.json → xlsx（openpyxl、uv 経由）。`--comments` でスレッドをセルのコメントにも書く |
| `assets/template.html` | 描画用テンプレート（serve.ts が埋め込んで配信） |
| `examples/sample.sheet.json` | サンプル（2 シート、結合・色・幅・行列固定あり） |
| `examples/confirm.sheet.json` + `confirm.review.json` | 確認メモ（確認スレッド）つきの例 |
| `~/.sheet-preview/` | ハブの状態（登録一覧・ごみ箱・整理ログ）。下の「ハブと ~/.sheet-preview/」 |

作業ファイルは、依頼された場所か、作業中のプロジェクトの適当なフォルダに置く。skill のフォルダには置かない。

## 2 つの用途

最初にどちらかを決め、sheet.json の `mode` に書く（HTML ヘッダーに表示される）。

- **スキーマ確認（`"schema"`）**: 列構成・見出し・結合・色・数式の置き場所など、枠組みを決める。セル値は空やダミーでよい。「備考欄はここ」「合計行は結合したい」のような指示が中心。
- **実データ確認（`"data"`）**: 実際の値を入れて、中身の誤り・抜け・並びを確認する。「この行の単価が違う」「C 列は千円単位に」のような指示が中心。

迷ったら、データがまだ無ければ schema、あれば data。

## 手順

### 1. sheet.json を作る
依頼内容（目的、必要な列、見せたい集計など）から `<名前>.sheet.json` を書く。まず `references/sheet-schema.md` を読む。`examples/sample.sheet.json` を雛形にするとよい。ヘッダー行は色を付け、列幅は内容に合わせる。見た目の確認が目的なので、シート数・行数は確認に足りる最小限にする。トップレベルに `"meta": {"task": "タスク名", "title": "表示名"}` を書くとタブ名・一覧に使われる（任意）。

### 2. ハブに登録して人に見せる
ハブは固定ポート（既定 8765）の常駐サーバ 1 つ。全タスク・全ファイルがここに載る。**起動も登録も同じコマンド**。

```bash
node <skill>/scripts/serve.ts <名前>.sheet.json --task <タスク名>   # 出力 1 行目が URL
node <skill>/scripts/serve.ts a.sheet.json b.sheet.json <フォルダ>   # 複数・フォルダ（直下の *.sheet.json を列挙）
node <skill>/scripts/serve.ts                                        # ファイル指定なし（一覧だけ開く）
node <skill>/scripts/serve.ts --stop                                 # ハブを止める
```

- ハブが未起動ならこのプロセスがハブになる（フォアグラウンド。**バックグラウンドで起動する**）。起動済みなら新しいサーバは立てず、ファイルを登録して URL を出して終了する。ポートを別プロセスが使っていればエラーで終わる（`--port` で変更）。
- 出力 1 行目は `sheet-preview: http://localhost:8765/?f=<絶対パス>`。**この URL を人に伝える**（エージェントの仕事）。`/` は一覧画面。
- `--task` はタブ見出しの `[タスク名]` と一覧の絞り込みに使う。sheet.json の `meta.task` でも指定でき、`--task` が優先。タスクごとにフォルダを分けて置く（`<作業場所>/<タスク名>/<名前>.sheet.json`）。
- 画面最上部は「一覧」タブ（常に先頭）とファイルタブ。ファイルごとに review・未保存・元に戻す履歴・下書き・競合検知が独立。未保存のタブには ●、外部更新があれば ⚠。起動後はタブ右端の「+」でも登録（無ければ新規作成）できる。
- ブラウザのタブ名は `[タスク名] ファイル名 - sheet-preview`。未保存の変更があれば先頭に ●、人の返事待ちの確認が n 件あれば `(n)`。favicon の色はタスクごとに変わる。
- API は `?f=<key>`（key = sheet.json の絶対パス。登録内で一意ならファイル名だけでも可）で選ぶ。`GET /api/ping` で生存確認（`{app:"sheet-preview", pid, port, ...}`）。`GET /api/files`・`GET /api/list` で一覧。
- 単体ファイルでの起動（`node serve.ts x.sheet.json`）も従来どおり動く（ハブに 1 件登録して URL を出す）。`--review` は 1 ファイルのときだけ。
- サーバを使わない場合は静的 HTML: `node <skill>/scripts/serve.ts a.sheet.json b.sheet.json --render all.html`。

### ハブと ~/.sheet-preview/
環境変数 `SHEET_PREVIEW_HOME` で場所を変えられる（テスト用）。

| パス | 内容 |
|---|---|
| `hub.json` | 常駐ハブの pid・port |
| `registry.json` | 登録ファイル `[{path, task, title, registered_at}]`。起動時にここのファイルも開く。ファイルが無くなれば一覧に「見つからない」と出て、そこから登録を外せる |
| `trash/<日時>/` | 整理（下記）で移したファイル。`manifest.json` に元の場所 |
| `cleanup.log` | 整理・復元・完全削除の履歴 |

**7 日整理**: 一覧（`/`）を開くたび、登録済みファイルのうち sheet.json と review.json の更新が**両方**とも 7 日より古いものを `trash/` へ移す（削除ではない）。安全策: 登録済みファイルだけが対象 / 開いているタブ・未保存のタブがあるファイルは対象外 / `trash/` の 7 日超は完全に削除 / 一覧上部に「n 件を整理（ごみ箱へ）」と場所・復元ボタンを出す。`--no-cleanup` で止め、`--retention-days N` で日数を変える。

- **残したいファイルは整理前に別の場所へコピーするか xlsx にする**（`to_xlsx.py`）。ハブは作業の足場で、保管庫ではない。人にもそう伝える。
- 復元: 一覧上部のごみ箱から「元に戻す」（`POST /api/trash/restore {id}`）。元の場所へ戻して再登録する。
- ハブを止める: `node <skill>/scripts/serve.ts --stop`。

### 3. 人が画面で直す・コメントする
人ができること（右クリックメニューかツールバー）。

- **広い作業領域**: データ範囲の外側にも、画面を埋めるまで（最低 +20 行・+8 列）うっすらした空きマスが続く。そこに入力すると、データ範囲が自動で伸びる。空きマスは保存されない（値を入れたセルだけが sheet.json に入る）。右のコメント一覧は「一覧」ボタンで折りたたみ、境界のドラッグで幅も変えられる（幅と開閉は覚えている）。
- **選択**: ドラッグ、Shift クリックで拡張、Ctrl/Cmd クリックで追加。列見出し・行見出しのクリックで列・行ごと。
- **コメント**: 範囲を選んで「コメント」。選択セルの近くに引出線つきの吹き出しが出て、右側に縦の一覧（スレッド。種類 指示 / 確認 / メモで色分け、返信入力・解決・開き直しつき）が並ぶ。一覧と吹き出しは連動する。確認待ちは強調され、「確認待ち」で絞り込める。確認に返信すると AI の番（未対応）に戻る。範囲欄に `明細!B2:D5, F3` と直接打ってもよい。
- **直接編集**: ダブルクリック、または選択して文字入力 / F2 でセルを書き換え（Enter 確定、Esc 取消）。行・列の挿入・削除、見出しのドラッグでの並べ替え、結合・解除、背景色・文字色、太字・配置、行高・列幅のドラッグ、行列の固定、シートタブの追加・削除・名前変更・並べ替え。Ctrl+Z / Ctrl+Shift+Z で元に戻す・やり直す。
- 行・列を挿入・削除・並べ替えると、コメントの範囲も追従する。範囲が丸ごと消えたコメントは「対象が削除された」と出る（スレッドの `deleted: true`）。

保存:
- **サーバあり**: 「保存」で sheet.json と review.json を書く（書くたび rev が +1）。画面は読み込んだ rev を覚えていて、保存時に先に更新されていれば 409 で止め、「エージェントが更新した。再読み込みするか」と出す（上書きしない）。スレッドの追加・返信・解決は即時に保存される（項目単位でマージ）。3 秒ごとにも更新を見に行き、エージェントの返信は再読み込みなしで出る。
- **サーバなし**: ブラウザの localStorage に退避される。「sheet.json をコピー」「指示をコピー」で JSON を出し、人がチャットに貼る。貼られた JSON はそれぞれ sheet.json / review.json として保存して続ける。

### 4. 往復（エージェントの仕事）
やり取りは**スレッド**（`references/review-schema.md`）。種類は 指示（人→AI の修正依頼）/ 確認（AI→人の質問。セル・範囲・行列・`シート!*`・`*` に付く）/ メモ。

**書き方は 2 通り。同時に人や他のエージェントが書いているので、サーバ API を優先する。**

#### A. API（推奨。競合しない）
- sheet.json: `POST /api/patch?f=<key>` に `{"base_rev": <GET /api/sheet で読んだ rev>, "ops": [...]}`。ops は `set`（`{op:"set", sheet, cell:"B2", v, bg, color, bold, ...}`、null で属性を消す）/ `format`（範囲）/ `merge` / `unmerge` / `freeze` / `colWidth` / `rowHeight` / `insertRows` 等 / `addSheet` 等。サーバが直列に適用し、rev を +1 する。**別の書き手が先に同じセルや構造を変えていたときだけ 409**（`conflicts` に該当セル）。ほかは古い `base_rev` でもマージされる。409 は GET し直して、状況を見て再送する。
- review.json: `POST /api/review/patch?f=<key>` に `{"ops":[...]}`。`add`（`{op:"add", range, text, kind?, name?}`）/ `reply`（`{op:"reply", id, text, status?}`）/ `status`（`{op:"status", id, status}`）/ `setRange` / `delete`。常にマージされる（409 なし）。応答の `results` に項目ごとの結果（`add` は採番した `id`）。
- 読む: `GET /api/file?f=<key>`（sheet と review と rev）。

#### B. ファイルを直接書く（サーバに触れないとき）
書く前に `<ファイル>.lock` を排他作成（`O_CREAT|O_EXCL`。既にあれば 25 ms 待って再試行、3 秒で諦める。10 秒以上古い lock は残骸なので消してよい）→ **ロックを取ってから**読み直す → 変更 → `<ファイル>.<pid>.tmp` に書いて `rename` で置き換え → `rev`（sheet.json はトップレベル `rev`、review.json も `rev`）を +1 → lock を消す。ロックなしの直接書き込み・書きかけの上書きは禁止（人の保存と競って片方が消える）。

#### 指示の処理
0. **人が直接直した場合、sheet.json はすでに変わっている。作業前に必ず今の sheet.json を読み直し、指示文より現在の sheet.json を優先する**。`range` は行・列の編集に追従済み。`deleted: true` のスレッドは対象が消えているので、「対象が削除されたため対応不要」と返信して `対応済` にするか、人に確認する。
1. status が `未対応` のスレッドを拾う（人の返信があるとスレッドは `未対応` に戻る）。
2. 各 `range` を sheet.json で確認し、最後の人のメッセージどおりに直す。
3. 曖昧なら勝手に決めず、`reply` に質問を書き `status: "質問"` にする。
4. 直せたら `reply` に何をどう直したか 1〜2 文を書き `status: "対応済"` にする。
5. 人は画面で自動更新を受け取る（3 秒ごとに差分を見に行く。未保存の編集があれば更新バナー）。

#### 確認メモ（AI が人に聞く）
作業中に人の判断が要る点（前提が不明、解釈が割れる、値の根拠が無い）は、書かずに確認を立てる。

1. `add`: `{"op":"add","range":"明細!C5","kind":"確認","text":"単価は税抜でよいか"}`。対象は A1 / 範囲 / 行 `明細!5:5` / 列 `明細!C:C` / シート全体 `明細!*` / ファイル全体 `*`。status は自動で `確認待ち`。画面ではセルに三角マーカー、右の一覧に「確認待ち」の強調と絞り込み、上部とタブ名に未回答件数が出る。**人に URL と「確認メモがある」と伝える**。
2. 返事を読む: `GET /api/review?f=<key>` で `messages` の最後の `author: "human"` を読む。人が返信するとスレッドは `未対応`（エージェントの番）になり、人が「解決」を押すと `解決`。
3. 返事の後: 内容を sheet.json に反映し、`reply`（何を反映したか）+ `status: "対応済"`。まだ足りなければ `reply` で再質問して `確認待ち` に戻す。人が `解決` にしたスレッドは扱い済み。再度必要になれば人が `未対応` に開き直す（開き直したら 1 から）。
4. 返事を待たずに進めてよい箇所と、止める箇所を分ける。確認待ちのセルに依存する作業は返事が来るまで確定させない。

review.json のスレッドは削除せず履歴として残す。人が「これでよい」と言うまで繰り返す。人の保存が競合すれば 409 で止まるので、人の変更が黙って上書きされることはない。

### 5. xlsx にする
```bash
uv run <skill>/scripts/to_xlsx.py <名前>.sheet.json <名前>.xlsx
```
`uv` 経由で openpyxl が自動で入る（pip は使わない）。`--comments` を付けると、隣の `<名前>.review.json`（`--review <path>` で変更）のスレッドを範囲の左上セルのコメントとして書く（既定は書かない。行・列・シート全体の対象は書かない）。結合・背景色・文字色・太字・配置・列幅・行高・固定行列（`freeze`）が反映される。列幅は px から文字数、行高は px から pt に近似変換する。数式（`=` で始まる値）はそのまま xlsx の数式になる。

### Google Sheets への書き込みは承認制
xlsx を Google Drive / Sheets にアップロード・書き込みするのは外部書き込み。書く内容（宛先・対象ファイル）を提示し、人の明示的な承認を得てから実行する。承認なしにしない。ローカルの xlsx 出力は承認不要。

## 指示の書き方（人向けの補足）
範囲は A1 形式。シート名は `!` の前に付ける（`明細!B2:D5`）。複数範囲はカンマ区切りで、シート名は最初の 1 回でよい（`明細!B2:D5, F3`）。別シートを混ぜるときは `明細!B2:D5, 集計!A1` のように書く。スペースや記号を含むシート名は `'月次 売上'!A1` と引用符で囲む。
