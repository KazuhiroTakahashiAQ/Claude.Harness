# review.json スキーマ

人の指示とエージェントの返答。ファイル名は `<名前>.review.json`（sheet.json と同じフォルダ）。

```json
{
  "sheet": "sample.sheet.json",
  "items": [
    {
      "id": "r1",
      "range": "明細!B2:D5, F3",
      "instruction": "備考列は幅を 2 倍にして折り返す",
      "status": "未対応",
      "agent_reply": ""
    }
  ]
}
```

| キー | 型 | 内容 |
|---|---|---|
| `sheet` | string | 対応する sheet.json のファイル名（保存時にサーバが入れる） |
| `items[].id` | string | `r1`, `r2` … 追加時に採番 |
| `items[].range` | string | A1 形式。複数はカンマ区切り。シート名は `!` 前置き（`明細!B2:D5, F3`）。シート名は直前の指定が次の範囲にも引き継がれる。スペース等を含む名前は `'月次 売上'!A1` |
| `items[].instruction` | string | 人が書いた指示 |
| `items[].status` | `未対応` \| `対応済` \| `質問` | 人が追加した時点では「未対応」。エージェントが処理後に「対応済」か「質問」にする。人が手で変えてもよい |
| `items[].agent_reply` | string | エージェントの返答（何を直したか / 何を聞きたいか）。人は書かない |
| `items[].deleted` | boolean（任意） | 行・列の削除で `range` の対象がすべて消えたとき、画面が `true` を付ける。画面には「対象が削除された」と出る。`range` は消える直前の位置のまま残る |

- サーバは保存時に status が上の 3 値か、range・instruction が文字列かを検証し、違えば 400 を返す。
- 範囲は画面での行・列の挿入・削除・並べ替えに追従して書き換わる。エージェントが読むときは、現在の sheet.json の位置を指していると考えてよい。
- 保存（`POST /api/review`）は読み込み時の版（mtime-size）を `base` で送り、ファイルが先に更新されていれば 409 を返して上書きしない。
- 項目は削除せず履歴として残す（人が UI で削除した場合を除く）。
- 「指示をコピー」で出る JSON は同じ形。チャットに貼られたらそのまま review.json として保存できる。
